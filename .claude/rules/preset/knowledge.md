# Where knowledge is kept

Anything worth keeping is written into the repository, so that a clone and a fresh session have it.
Auto memory outside the repository is machine-local and keyed by the repository's location; it is
not relied on for anything the project needs.

- **Useful or needed for the project**: write it down as a document. Authoritative project facts
  and decisions go to the project's documentation and decision record; working material goes at
  least to the internal research cache.
- **Useful as context rather than documentation**: write it to the research cache as cold storage.
  Extract the valuable parts of long prose, complex files, and websites once, with the source and
  access date, so they are not reread. The `research-topic` skill gives the format.
- **The artefact stands on its own.** Its documents describe what it is; the context of the project
  that produces it (people, institution, supervision, schedule, coursework documents) lives in the
  project's main paper, named in `CLAUDE.md`, and is referenced only when a task concerns the
  project.
- **Once code exists**, status catalogues (a feature inventory, a requirement catalogue) are the
  authority on what is implemented, not `CLAUDE.md`.
- When the user asks to remember something that is durable and project-relevant, propose where it
  belongs (a rule, a document, or the cache) rather than saving it only to auto memory.
